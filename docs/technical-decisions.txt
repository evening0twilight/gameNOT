3. 目录与依赖方向
游戏根为game/，唯一产品工程为game/project.godot。
game/data/final_design/design_manifest.json -> release_baseline.json是唯一0.18规则入口。
manifest.generated_views列出的JSON是导出投影，不可手改；修改基线后运行
python3 work/predevelopment-review/export_views.py，并同步期望夹具、手册和决策。
32个领域、36地图、96场景使用同一数据契约，不写每关一套规则。

game/scripts/domain/：无节点树、输入、音视频、文件IO的纯规则与状态转换。
game/scripts/app/：流程协调、命令提交、阶段切换、单一状态所有者。
game/scripts/infrastructure/（按需创建）：数据载入、存档、平台与日志适配。
game/scripts/presentation/、game/scenes/（按需创建）：界面、棋盘、表现；只读快照、提交命令。
game/assets/（按需创建）：实际产品资源；素材清单见docs/asset-register.csv。
game/tests/：Godot规则、集成、持久化和契约测试；tools/：仓库验证与构建工具。
work/：离线Python裁判和历史证据，禁止成为产品运行时依赖。
outputs/：设计阅读页与既有检查证据；build/：可重建测试产物；archives/evidence/：压缩历史证据。
依赖：presentation -> app -> domain；infrastructure实现app需要的持久化/载入边界。
不得反向由domain访问UI；不使用全局单例堆放各模块可任意写入的Dictionary。
现有save_store.gd在domain目录但实际做IO，是旧准备模块；P1迁入infrastructure并补迁移测试。
现有relationship_rules.gd只有旧关系模型，不能当0.18完整实现直接验收。

4. 状态、命令、统一预览执行和事件账本
接口详细定义见docs/contracts/runtime-v1.json；这是下一阶段实现约束，不是已实现API。
CampaignState唯一写入者为app层Session；子域battle/actors/inventory/social/story/tutorial共用revision。
所有运行时内容先通过ID/范围/引用/地图维度/重复ID/有限数值校验，再生成不可变目录。
JSON外部输入一律验证类型，不依赖Dictionary默认值把缺字段变成合法规则。

reduce(snapshot, command, content) -> Result。预览与执行调用同一个纯函数。
预览在深复制状态上运行，不消耗真实RNG、不写资源/账本/存档，不发可产生副作用的信号。
预览返回合法性、逐项成本、结果、已知风险与预期revision；UI不另算AP/伤害/关系。
执行先检查expected_revision和唯一command_id，再计算候选状态；陈旧预览拒绝并刷新。
遇到实质风险变化按0.18重新确认，基础行动不因关系被剥夺。
成功先完成候选快照和事件的持久化事务，再发布新的内存状态与表现事件。
任何预检/写盘失败不改变AP、资源、RNG、事件序号、记忆或任务结算标记。
动画、跳过、读档、界面重建均不触发规则执行。输入重复点击由command_id返回原结果。
只允许稳定动作边界保存；动画期间状态已提交，恢复时可直接呈现稳定结果。

账本是事实记录，状态快照是恢复入口；不在读档时把全部事件重放一遍再发奖励。
事件字段遵守integration.receipt_schema；事件ID沿用campaign/mission/command_index/type/object。
新增seq用于排序；同命令同类型同对象须合并为一条事实，不靠遍历顺序制造重复ID。
root_decision_id归并同一决定的多项后果；observer_ids与information_scope控制知情范围。
同一campaign/mission只结算一次，奖励、经验、加入、证据与人物核验同一事务提交。
social为情绪/记忆权威，营地仅显示投影；账本/快照两者均不得被UI独立写入。
规范化哈希按对象键排序、集合转有序数组；路径/并列目标按稳定ID排序。
AP/格坐标/资源等用整数；有向关系权重有界且拒绝NaN/Inf，浮点比较按明确容差。
RNG保存seed和state的十进制字符串，避免JSON浮点丢失64位精度；不依赖系统时间/字典顺序。
不同引擎版本不承诺相同随机序列，跨引擎读档须走明确迁移策略。

5. 存档契约
产品存档schema从2开始；现有schema=1是准备容器，不能静默当正式周目读取。
正式路径user://saves/<slot_id>/，元数据与完整状态同一快照封装，不分散多文件事务。
包括format/schema_version/content_version/content_sha256/engine_version/campaign_id/revision、
状态、账本seq和去重集合、rng、校验和。每个字段的具体0.18清单以persistence_inventory.snapshot为准。
清单中的training_completed、首次工量/AP转交标记、难度部署快照、记忆、剧情、教程均不可遗漏。
偏好设置与通关解锁档案分开；新周目不继承等级/资源。

写入流程：候选序列化到同目录.tmp -> flush/close -> 重新解析并校验 -> 保留有效.bak ->
替换当前槽 -> 返回成功，再提交内存；失败保留之前有效档并返回可重试错误。
加载先校验尺寸上限（初始64MiB工程保护值，超限明确报错，不截断）、结构、schema、内容指纹、
全部ID和状态不变量，再构造临时状态，全部成功才替换Session。
正式实现须测试在backup切换后崩溃的恢复：主档缺失/损坏时保留并提供有效备份恢复。
未知较新schema拒绝读取且不覆盖；旧正式schema用逐版本纯迁移函数并保留原件。
准备schema1提示“开发准备档不兼容”，不虚构可恢复战役。
内容变更须提供旧内容到新内容ID映射或明确拒绝；不能只改版本号绕过校验。
校验和只检测损坏，不声称防作弊。flush/rename不等于掉电耐久证明，Windows故障注入必须实测。

6. 编码与资源规范
UTF-8、LF、文件末尾换行；GDScript用tab、显式类型、snake_case文件/方法/变量、PascalCase类。
新代码一函数一职责，公共接口说明输入、输出、失败语义和是否产生副作用。
不引入“返回空字典代表所有错误”；统一Result及error_code，用户可见错误翻译成明确中文原因。
断言用于开发不变量，不能替代坏档/缺文件/非法输入的产品错误处理。
捕获文件/解析失败并向上报告；禁止吞异常、print后仍标记成功。
日志记录build/content/revision/command/event/error；默认不输出全量存档或私有机器路径。
源文件与资源路径用ASCII snake_case，显示名可中文；保持大小写一致，避免Windows/macOS差异。
Godot .uid、.tscn、.tres、.import资源设置须跟踪；.godot导入缓存不跟踪。
当前无需为“代码整洁”重写历史探针；只约束新实现，改旧工具必须保留回归证据。

美术源文件与导出文件分开管理；产品只放必要导出资源，超大源文件另作可验证归档。
2D使用可复用角色标记/地点套件，不做3D和骨骼流程。字体必须有简体中文覆盖及许可文件。
一般插画默认线性采样；只有明确像素素材才用nearest。纹理先≤2048，例外记录实际显存收益。
短音效WAV，音乐OGG；避免将无损音乐母版打包到产品。具体压缩以Windows听测为准。
1440×900设计基准，容器/锚点布局；1280×720/1080p/1440p及三档字号测试，不用固定像素裁切正文。
禁止信息只靠颜色；交互须有确认/取消/无法行动时的出路。
每个素材登记ID、作者/来源、许可与证据、修改、用途、状态；生成素材另记工具/模型/日期/原始产物。
未验证授权的占位资源不能标记release-approved。代表人物/棋子/场景用户审美确认后再批量制作。
