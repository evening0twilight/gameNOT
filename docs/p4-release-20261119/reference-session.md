# Windows 参考机记录

**给观察者。** 先完整解压候选包。首次试玩的人只需从游戏标题开始。请观察者操作记录工具、保管结果，在试玩结束后访谈。攻略、测试脚本和带有剧情的验收表由观察者阅读。

## 开始一次正常游玩

在 Windows 11 x64、实际安装 8 GB 内存的参考机上，把桌面设为 1920×1080。冷启动测试应在解压后重启 Windows。重启后首次运行本候选时，双击 **Record-Windows-Session.cmd**。游戏以全屏方式打开；正常新建周目或读档。保持记录窗口开着，退出游戏后等它显示结果目录。记录器使用系统自带的 Windows PowerShell 5.1，启动参数只对当前进程有效。

记录写入“文档”下独立的 NightTide-Review 日期时间目录。保留整个目录和所用 ZIP 的文件名。device.json 中的 EXE/PCK 哈希应与包内收据相符，检查退出码及游戏记录是否齐全。若进程被强制关闭、系统重启或记录窗口意外退出，保留已经写出的数据并注明中断。记录中没有键码、文字输入、玩家姓名或存档内容。

## 对照 R07

| 项目 | 观察方式与判断 |
| --- | --- |
| 机器 | device.json 记录 Windows 版本、系统架构、CPU 架构编码与名称、GPU/驱动、物理内存。CPU 架构编码 9 为 x64。game-metrics.json 另记实际渲染 GPU 和窗口尺寸。缺失设备数据时由观察者补记。 |
| 冷启动 ≤10 秒 | 在观察单写明“重启后的首次运行”、是否有系统提示和屏幕上标题何时可操作。device.json 中的 launch_to_title_signal_upper_ms 从启动进程前计到首次标题 post-draw 标记被轮询发现，包括创建进程和约 25 ms 轮询粒度。脚本在游戏退出之后才读取整包哈希。这个数不能验证硬件扫描输出的最后一段时延。 |
| 稳定棋盘 95% 帧 ≤16.7 ms | 在有实际人物、机器和目标的现场保持游戏前台，关闭弹窗和预览，采集几段足够长的静止棋盘，记下任务、停留时段与刷新率。game-metrics.json 只统计窗口 1920×1080、出勤状态稳定至少一秒、无动画/模态窗口时连续两次渲染完成的间隔。核对 stable_1080p_frames、stable_seconds 及 stable_fraction_le_16_7_ms 是否 ≥0.95。零样本或仅一瞬间不支持判定。p95 字段以 0.1 ms 桶上界表示。 |
| 输入反馈 ≤100 ms | 观察者让玩家自然使用键盘和鼠标，覆盖现场定位、预览、确认，以及营地或剧情选择。input-feedback.csv 按触发的具体指令记“游戏收到事件到下一次渲染完成”，并保留超出 100 ms 的行；按下/松开以实际触发命令的事件为起点。只切换焦点、单纯滚动等不会产生指令记录。检查 game-metrics.json 中的 input_samples、input_over_100_ms 与 input_max_ms。实际从物理输入到屏幕上首次可见反馈的明确结论，需要外部观测同时看到按键/鼠标与画面，例如 120 fps 或更高的逐帧录像。写下动作、帧号与帧率，遇到边界值时保留时间分辨率。 |
| 连续两小时内存无持续增长 | 在同一游戏进程中实际玩满两小时，覆盖出勤、结算、故事和营地，记录几次返回相似负载界面的时间。process-memory.csv 约每分钟记录一次进程 private_bytes 与 working_set_bytes；以私有内存为主要判断依据。建议留出额外两分钟以覆盖首尾采样。结合 process_seconds、memory_sample_span_seconds 及最长采样间隔核实完整性，排除睡眠或长时间离开。对照阶段笔记看初期加载后是否趋稳、重复场景是否仍阶梯式上升。报告完整曲线及判断理由；两个端点或仅仅运行满两小时都不足以判断。 |

## 自动检查

**Run-Windows-Checks.cmd** 单独执行三段任务、对照提交与保存，并在新目录写出 report.json、结果截图、引擎日志和 device.json。它使用独立的测试存档。先做冷启动记录，再运行自动检查，以免提前加载游戏文件。自动结果要求 `native_windows=true`、所有断言通过、正常退出且 EXE/PCK 指纹一致。

本轮开发机使用隐藏根窗口和 GPU SubViewport 验证了标题标记、真实界面控制中的脚本鼠标事件和确认弹窗。隐藏 720p 场景的稳定 1080p 样本为零。macOS 上还检查了 PowerShell 脚本语法与模拟进程记录，自动任务报告标记为 macOS。这些证据只涉及记录工具的工作方式；本候选的 R07 和真人试玩须保留实际 Windows 参考机及玩家数据。

### 本轮发现的首场等待

开发机首次确认“出发”后，要同步解码三位队员的身体、动作图集以及首图地面、居民、机器、作业图标。现在新建周目在阅读渡轮简报时后台准备这十张纹理，并保持引用至棋盘绘制完毕。标题冷启动和读档沿用原有加载路径。

同一 Mac、隐藏 720p GPU 视口、同样的实际简报与确认按钮，修前独立进程中的三次合成鼠标确认到 post-draw 分别用了 670.2、396.7、292.5 ms。返修后三次用了 74.8、83.2、88.6 ms。结果含进程间缓存及机器负载波动。可复核的输入记录、同步提交与绘制构建时间见 reference-software.json；评估 Windows 参考机时仍须使用实际设备和真实输入。
