# 周目和手动存档的恢复

2026-11-19，macOS、Godot 4.7.2、Apple M3，隐藏根窗口，1280×720 GPU 视口。通过游戏界面新建两个普通周目。检查脚本只在它自己创建的专用目录注入存档损坏。

| 情况 | 修复前 | 本轮结果 |
| --- | --- | --- |
| A 的主自动存档损坏，另一个周目 B 是活动周目 | 读档器可以读 A 的备份，标题「选择周目」却只显示 B | 列表同时显示 B 和「A · 恢复备份」。关闭 A 的恢复来源窗口后，当前会话与磁盘配置都保持 B。再次选择 A 并点击其自动备份，会进入 A，原损坏内容逐字保存在 .damaged 文件中。 |
| 活动周目只剩编号手动槽的上一份备份 | 启动路径只判断主自动档或其备份，手动槽列表只给编号主文件提供读取入口 | 退出并重新启动引擎后，标题隐藏「继续」，提供「读取手动存档」。第 01 槽显示第 1 日、任务简报阶段和实际来源 manual-01.json.bak。简中、繁中、英文逐一通过实际语言按钮验证，最后以英文选择该槽并恢复原周目。 |

两个周目均在正式新建窗口确认创建。A 在简报中通过顶部菜单把进度写入第 01 槽，确认首场出发；按 Esc 打开暂停菜单并返回标题，再建 B。选择周目、手动槽、语言、救援和出发确认均以脚本按压实际控件。取消恢复使用 Godot 窗口的标准关闭信号。测试对后续文件进行定向损坏、移除或改名，以构造上述恢复条件。手动槽成功后也重新读取磁盘主档，核对其与 A 的身份一致。

## 本地复跑

在仓库根目录运行以下命令。脚本默认使用锁定的 macOS Godot，可用环境变量 `GODOT` 指定同版引擎；项目需先完成资源导入。此脚本需要本机可创建符号链接。它会给临时工程创建唯一名称，两个独立引擎进程共享该名称的专用用户数据。验具会在打开游戏场景前核对临时工程及用户目录；结束后入口只清理本次生成的同名目录。

```sh
python3 tools/review_release_slots.py
```

原始复现和最终操作日志分别保存在 `outputs/p4release-20261119-slot-before.log` 与 `outputs/p4release-20261119-slot-recovery.log`。本项验证涉及真实存档与界面接线；Windows 包实测、真人发现恢复入口的难易度由各自验收记录覆盖。
